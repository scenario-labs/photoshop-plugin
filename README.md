# Scenario for Photoshop

A UXP plugin that brings [Scenario](https://www.scenario.com) generation into Adobe Photoshop, and a local MCP server, `scenario-photoshop`, that lets agent clients (Claude Code, Codex, Cursor, Claude Desktop) work with it.

**Status: early build (milestone M3). It signs in to Scenario, browses the model catalog, shows exact prices, and generates in the Image lane: a click on Generate spends the CU shown on the button and places the result in your document.** The other lanes show their price and stay disabled. Its Scenario calls are reads (the key check, the model list and schemas, job status, result records), free price checks (dry runs, which create no job and spend nothing), the paid generation request when you click Generate, uploads of the references you add (at Generate) and, for models whose price needs an image input, one blank stand-in image uploaded to the project and hidden from the Library.

Each statement below carries how it was checked: *verified live* (in Photoshop), *tested automated* (Node test suite, no Photoshop), or *not tested*.

## What this build does

- **Plugin** (`plugin/`): a compact panel in Photoshop's own style (12 px text, small controls, outline icons in the theme's text color, so it follows the four interface brightness themes). One header row: the Scenario mark, the project name, a dot for the agent link and the Jobs icon with a count badge. One row of lane tabs (Image, Edit, Enhance and Trained work as below; Library is a placeholder), a body that scrolls, and the prompt bar with **Generate** pinned at the bottom. Settings, Projects, Connect an AI Agent, Diagnostics, Help, About and Sign Out are in the panel menu. Settings > Connect an AI agent holds the link status and the pairing token (Copy; Show and Reset under Details). Its startup code runs when Photoshop launches, even with the panel closed, and dials the helper on `ws://localhost:9890`; it calls Scenario only once the panel is shown or an agent asks. *Tested automated* (the built bundle runs in a fake UXP host). *Verified live* on Photoshop 27.11: the development build loads at launch and links to the helper. The panel itself was not looked at.
- **Sign-in**: paste a Project API key and its secret (pasting `key:secret` or the two on two lines fills both fields), then **Save and test**. The plugin makes two free reads on Scenario's API, an authenticated read and the project listing, and saves the key in UXP secure storage only when both pass. The panel header then shows the project name, or `Scenario project ....` and the key's last 4 characters when no name is readable. A key for another project can be added and switched from the project name in the header; Settings (in the panel menu) has **Test connection**, **Sign out** (the current project's key) and **Copy diagnostics**. Development builds can also be signed in from a `dev-api-key` file in the data folder, through the same check (see AGENTS.md); release builds do not contain that code. A refused key, a Reader key, a team (Organization) key and no connection each get their own message. *Tested automated* against a mock of Scenario's API that answers as the live API did, including a test that the key, the secret and the listing's member emails and key ids never reach logs, files, the helper, `scenario_status`, the panel or the clipboard. *Verified live* on Photoshop 27.11: Save and test and the save to secure storage, through the development key import. *Not tested* in Photoshop: typing or pasting into the fields, reading the masked secret field on macOS, and secure storage removal.
- **Model catalog**: the model list (the project's own models, then Scenario's public catalog) is read when the panel is first shown, cached in the plugin's data folder and refreshed in the background once a day. Models are sorted into the Image, Edit, Enhance (Upscale, Expand, Remove BG) and Trained tabs from their tags and capabilities; deprecated models are hidden. **Change model** opens the picker: search, chips (All, Favorites, Recommended, and per tab References, Mask input, the Enhance tools, This project or Public), a tag menu, and favorites kept in the data folder. Recommended lists the lane defaults, then models Scenario features. Trained models (LoRAs and compositions) can be browsed, with their kind and base model, but not used yet. *Tested automated*. *Not tested* in Photoshop.
- **Lanes and prices**: each lane opens on its default model (Image and Edit: GPT Image 2.5 Flare at low quality; Upscale: Topaz Image Upscale at 2x; Remove BG: 851 Labs) with a prompt, a size, takes and, for Upscale, the factor. The form is checked against the model's schema before any price check, then priced 400 ms after the last change, and the price shows on the button: `Generate (2 CU)`. Prices can be exact, a range or a `from` price. Outside the Image lane the button stays disabled ("Generating here is not in this version yet."); Expand and Trained say why they show no price yet. *Tested automated* in a DOM built from the panel's HTML, against a mock of Scenario's API that answers with responses recorded from the live API: Image default 2 CU, Edit default with a mask 3 CU, Remove BG 1 CU, Upscale 10 to 60 CU by document size. *Not tested* in Photoshop.
- **Price checks**: the dry-run flag is written once, in one constant. The plugin's API client lets a request to Scenario's generation endpoint through only as a price check carrying that constant, or as the paid request carrying its own marker and no query string at all; anything else is refused before it is sent. Tests assert the exact query string of every price check and that no paid request carries the flag. Image inputs a lane fills from the document later are priced without document pixels: by count where the price follows the number of files, or with a blank image of the right size where it follows their size. A price check that comes back with a job stops all price checks and says so in the panel. Each price is a quote that lasts 120 s, is used once and is bound to the exact request. *Tested automated*.
- **Generate (Image lane)**: the prompt, the model from the picker, its settings (size preset, takes) and the target: the canvas, the selection's box (the result lands masked to the selection), or a new document when none is open. A click on a priced button is the approval; above the confirm limit (100 CU; the top of a range; always for a `from` price) a card asks first. The request is built again at the click, so a document, selection or setting changed since the price check makes the quote mismatch and nothing is spent. The job record is written before anything is sent, keyed by the quote (a second click with the same quote sends nothing). The paid request goes once and is never retried: no answer within 60 s, a lost connection, a 5xx or an unreadable answer makes the job **Unknown**, which blocks the same request until you mark it not sent in Jobs; 400, 401, 402, 403, 404, 409, 413, 422 and 429 are not sent and charge nothing (a 429 pauses Generate for its Retry-After). The job is then polled (every 2 s, then 5 s, then 15 s), and the charge read from Scenario: a failed job shows "Refunded by Scenario". *Tested automated* against the mock API answering with the paid-job responses recorded live, through the plugin source on the real host adapter and through the release bundle, both over a fake Photoshop. *Not tested* in Photoshop.
- **References (Image lane)**: add the selection's box, the active layer, all visible, or a PNG or JPEG file. Captures are read as 8-bit sRGB at most 2048 px on the long side, sent as JPEG when the model takes it (Photoshop encodes it) and as PNG otherwise (the plugin's own encoder). Uploads go only through Scenario's API and must stay under 4,000,000 bytes: a capture read again 10% smaller until it fits shows **Input reduced**; a chosen file loses its metadata and is refused if still too large. References upload when you click Generate; a price that changes once they are uploaded stops there and asks you again. *Tested automated*. *Not tested* in Photoshop.
- **Results**: each result downloads from Scenario's CDN (no key sent; the measured redirect is followed and its final host checked) into a `.part` file renamed when complete, three attempts, into the Output Folder in the plugin's data folder (`Scenario/image/<date>/...`). It lands as an embedded smart object scaled to cover the target and centered on it, in one History state ("Scenario: Place image"), and your active layer is made active again. Several takes land as a group with take 1 visible. Each layer carries Scenario metadata (XMP schema 1: model, prompt, settings, ids, prices quoted and charged). A result lands by itself only in the Photoshop session and document that started it; otherwise the tray and Jobs offer **Place** and **Open as document**. *Tested automated* on a fake Photoshop. *Verified live* on 27.11 with a probe plugin: placing a file as an embedded smart object, its frame, scaling, one History state, layer XMP and layer masks. *Not tested* live as part of this build.
- **Jobs**: the Jobs icon in the header (or Jobs in the panel menu) opens the jobs started on this computer, newest first, with status, the price words ("quoted 2, charged 2 CU", "Refunded by Scenario", "Nothing charged") and the actions this build has (Place, Open as document, Resume download, Approve or Decline a changed price, Mark not sent for an Unknown job, Copy error). After a Photoshop restart, a job that was being sent becomes Unknown, one that was uploading becomes not sent, and running jobs resume polling and downloading; nothing lands by itself. *Tested automated*.
- **Helper** (`helper/`, npm package `@scenario-labs/photoshop-mcp`, command `scenario-photoshop`): an MCP server over stdio with four tools. `scenario_status` reports whether the plugin is linked, the Photoshop and plugin versions, whether the plugin is signed in and the project name (never the key), the agent switches and spending settings, and the open documents (ids and titles). `list_models` and `model_schema` read the catalog; `estimate_cost` validates a request and returns a quote from a free price check. *Tested automated*, through a real helper process. *Verified live* on Photoshop 27.11: this build loads, links and answers `scenario_status`. `list_models` and `estimate_cost` were also *verified live* (0.3.1, signed in): the three recorded prices, 2, 3 and 1 CU, came back exact.
- **Several clients at once**: the first helper owns port 9890 on `127.0.0.1` and `::1`; later helpers relay through it; when the owner exits, another takes over and the plugin reconnects. Each client gets a session (a random 128-bit id, new each time the plugin links) and keeps the name it gave at its first `initialize`; the panel lists clients by that name, and the plugin refuses calls from a session that is not on its list. *Tested automated* (macOS). *Not tested* on Windows.
- **One Photoshop at a time**: if a second Photoshop with the plugin reaches the helper, it is refused and its panel says "Agents are connected to another Photoshop"; the first keeps the link. *Tested automated*.
- **Pairing**: the plugin makes a 256-bit token and keeps it in UXP secure storage. The token never travels over the socket: both sides prove they hold it with HMAC-SHA-256 over fresh nonces, then every message carries a MAC and a counter. The helper also checks the `Host`, `Origin` and `User-Agent` headers before any protocol byte. *Tested automated*, including wrong tokens, replayed and tampered messages, programs squatting on the port, and browser-like connections.

## Connect an agent client (development)

The setup command reads the pairing token from the `SCENARIO_PHOTOSHOP_TOKEN` environment variable (or stdin with `--token-stdin`), never from a command argument. It writes the token to a file only your account can read (`~/.config/scenario-photoshop/token`, or `%APPDATA%\scenario-photoshop\token`), then registers the server with the client without the token: through `claude mcp add` or `codex mcp add`, or in the Cursor or Claude Desktop config file (with a backup of the old file).

```sh
# Token copied from the Scenario panel; nothing is written to your shell's argument list.
pbpaste | node helper/bin/scenario-photoshop.js setup claude-code --local --token-stdin
```

*Tested automated* with temporary home folders and a stand-in for the client CLIs. *Not tested* against the real `claude` and `codex` CLIs or on Windows. The npm package is not published yet.

Node 20 or later.

## Privacy

This build sends your API key and secret only to Scenario's API (`https://api.cloud.scenario.com`), as HTTP Basic authentication over HTTPS; it never follows a redirect with them. Of the project listing it keeps the project name, the project id and the key's own role; the listing's member emails and other keys are dropped at once. Price checks send the prompt, the model and its settings to Scenario's API, and never pixels from your documents: where a price needs an image, the plugin uploads a blank image (`photoshop-standin-<width>x<height>.png`) once per project and size, hidden from the Library. When you click Generate, the prompt and settings go to Scenario's API as the paid request, and the references you added are uploaded to your project through Scenario's API (`photoshop-reference-<date>-<id>`), never to another host. Results download from Scenario's CDN (`https://cdn.cloud.scenario.com`) without your key, and model pictures load from its public thumbnail path, also without your key. The plugin's data folder keeps the model list, the stand-ins' asset ids, your favorites, the job records (prompts, settings, document titles, ids and prices) and the downloaded results. Links you click open in your browser after Photoshop asks. Otherwise the only network use is the loopback link between the plugin and the helper. See [PRIVACY.md](PRIVACY.md) for the full design.
