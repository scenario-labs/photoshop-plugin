# Build status

What each part of the plugin does, at the level of detail a reviewer or contributor needs, with how it was checked: *verified live* (in Photoshop), *tested automated* (Node test suite, no Photoshop), or *not tested*. For using the plugin, read the [User Guide](USER_GUIDE.md); for what is missing, [Known limitations](KNOWN_LIMITATIONS.md).

Build: 0.7.1 (milestones M1 to M7 on one branch; M8, the illustrated docs and media, done on 2026-10-20). The M8 live pass on Photoshop 27.11 with 0.7.1 dev is in the section **M8 live pass** at the end.

Each statement below carries how it was checked: *verified live* (in Photoshop), *tested automated* (Node test suite, no Photoshop), or *not tested*.

## What this build does

- **Plugin** (`plugin/`): a compact panel in Photoshop's own style (12 px text, 13 px for the action, small controls, outline icons in the theme's text color, so it follows the four interface brightness themes). One header row: the Scenario mark, the project name, the agent icon with its dot and client name, and **Jobs** with a count. Below it: the context card (a picture and two lines, what is selected and where the result lands, with the progress while a run is generating), the action chips for that context (at most six, then **More**), then the Takes card and Recent in the part that scrolls, and the composer pinned at the bottom: the references row, the prompt (or one line for an action without one), the chips that set the model and its settings (each shows its value), the action button with its price and the settings icon. Projects, Settings, Connect an AI Agent, Diagnostics, Help, About and Sign Out are in the panel menu. Settings > Connect an AI agent holds the link status and the pairing token (Copy; Show and Reset under Details). Its startup code runs when Photoshop launches, even with the panel closed, and dials the helper on `ws://localhost:9890`; it calls Scenario only once the panel is shown or an agent asks. *Tested automated* (the built bundle runs in a fake UXP host). *Verified live* on Photoshop 27.11: the development build loads at launch and links to the helper. The creation panel in Photoshop: see **Look and live checks** below.
- **Sign-in**: paste a Project API key and its secret (pasting `key:secret` or the two on two lines fills both fields), then **Save and test**. The plugin makes two free reads on Scenario's API, an authenticated read and the project listing, and saves the key in UXP secure storage only when both pass. The panel header then shows the project name, or `Scenario project ....` and the key's last 4 characters when no name is readable. A key for another project can be added and switched from the project name in the header; Settings (in the panel menu) has **Test connection**, **Sign out** (the current project's key) and **Copy diagnostics**. Development builds can also be signed in from a `dev-api-key` file in the data folder, through the same check (see AGENTS.md); release builds do not contain that code. A refused key, a Reader key, a team (Organization) key and no connection each get their own message. *Tested automated* against a mock of Scenario's API that answers as the live API did, including a test that the key, the secret and the listing's member emails and key ids never reach logs, files, the helper, `scenario_status`, the panel or the clipboard. *Verified live* on Photoshop 27.11: Save and test and the save to secure storage, through the development key import. *Not tested* in Photoshop: typing or pasting into the fields, reading the masked secret field on macOS, and secure storage removal.
- **Model catalog**: the model list (the project's own models, then Scenario's public catalog) is read when the panel is first shown, cached in the plugin's data folder and refreshed in the background once a day. Models are sorted into the Image, Edit, Enhance (Upscale, Expand, Remove BG) and Trained tabs from their tags and capabilities; deprecated models are hidden. The composer's **Model** chip lists the action's recommended model, then up to eight catalog models that can do the action, then **All models...**, which opens the picker: search, chips (All, Favorites, Recommended, and per tab References, Mask input, the Enhance tools, This project or Public), a tag menu, and favorites kept in the data folder. The **Style** chip offers **No style**, **Match an image** (a picture from the selection, a layer, all visible or a file goes as the run's style reference, with any model that takes references) and the project's trained styles (LoRAs and compositions), on the edit actions and on Create image, New layer and Add background. A trained style runs on the model it was trained on: the Model chip switches to that base, with **Change** for the image and strength route. The Model menu shows each model's price for this document, the project's trained models (**Run with**, characters first), and under a trained style the trained models that stack with it on its base. *Tested automated*. *Not tested* in Photoshop.
- **Actions and prices**: each context offers its actions (SPEC 3.2). No document: Create image. A layer: Make versions, Extend canvas, Upscale, Remove background, New layer. A cut-out layer (masked, or smaller than the canvas): Add background first. A selection: Replace inside, Remove, Make versions, Cut out subject (on a new layer; the layer stays as it is, the selection is dropped in the same History state and the new layer becomes the cut-out context). A group of takes: Compare takes, More like this, Refine, Upscale kept take. **More** lists the context's other actions that run in this build, in groups; a pin adds one to the chips, kept per context in the data folder. Each action opens on its default model (Ideogram 4.5 Precise Edit for Replace inside and Ideogram 4.5 for Remove, from a comparison of four masked models on 2026-10-20; GPT Image 2.5 Flare for images, the other edits and Extend canvas; at Medium quality unless the settings icon picks High or Low; Topaz Image Upscale at 2x; 851 Labs Background Remover) with the chips it needs (edit, style, model, takes, size, target, factor, change amount). Replace inside's **Edit** chip reads Inside selection (everything outside the selection stays as it is) or Bolder (GPT Image 2.5 Flare, a stronger change: the mask of each take grows over what the model drew past the selection, up to 60% of its area, and the layer metadata records by how much). The checks tell a picture that moved (**May be misaligned**, a shift of 1 px or more away from the edit) from one the model re-rendered in place. Remove, Make versions with an empty prompt and Extend canvas send a built-in prompt, written in SPEC 3.5. The form is checked against the model's schema before any price check, then priced 400 ms after the last change, and the price shows on the button: `Replace inside · 3 CU`. Prices can be exact (`Free` for zero), a range or a `from` price; an action that needs a prompt reads `Fill in the prompt to see the price` until it has one. After a run that is not masked to a selection, the new group or layer is selected, so the next action works on the result. *Tested automated* in a DOM built from the panel's HTML, against a mock of Scenario's API that answers with responses recorded from the live API (one Flare take 2 CU, an edit with two takes 3 CU, 851 Labs 1 CU, Topaz by document size). *Not tested* in Photoshop unless marked below.
- **Later flows (P2)**, each priced and run like the others, landing in one History state with Scenario metadata whose kind keeps the new layers out of the Takes card: **Render sketch** (GPT Image 2.5 Sunburst, High), **New angle** (Qwen Edit Multiangle 2511: turn left or right 45°, side, back, from above; no prompt), **Relight to scene** (GPT Image 2.5 Sunburst; a cut-out or split element relit to the visible image, masked to its outline), **Split into layers** (Seedream 5.0 Flash Layerize: a group with the rebuilt background and one layer per element, each element found again where it was in the source by comparing its pixels; an element with a poor match is named in a note), **Remove text** and **Split text** (Ideogram V3 Layerize Text: the clean base as a layer, or a Text layer masked where the source differs from it over the clean base), **Select by description** (the Select… field under the context card's title; SAM 3.1 Image; the masks become the selection), **Formats** (Smart Reframe to 1:1, 4:5, 9:16 or 16:9 as an artboard of a "<title> formats" document), **Animate** (Minimax H3 Fast, 5 or 10 s at 480P; the clip opens as a new document) with **Frame to layer** (the clip's last frame as a layer, then Animate again from it), **Open from Library** and **+ Reference > Library** (a grid of the project's images, see M7 below), the Upscale result card comparing the same region at 100%, Suggest telling Prompt Spark the size the result fills, the Style chip and a cut-out's transparent background, and the agent's plan card (one card, each step's price, one total; the agent link does not send plans yet). *Tested automated* (the requests, the placement plans, the element finder on synthetic scenes and on six real splits, of which five landed right; the lighthouse of a relit split still lands on water). *Verified live* on Photoshop 27.11 with the 0.6.2 development build (one smallest run each, 2026-10-20, every job applied as its record shows): Render sketch, the Upscale 100% compare, Select by description, Split into layers, Remove text, Split text, Formats at 9:16 (a first try failed on Scenario and was refunded), Animate, Frame to layer, New angle and Relight to scene. *Not tested* live: the plan card (the agent link does not send plans yet). Start a set, Same action on each and Run a workflow are not in this build.
- **Price checks**: the dry-run flag is written once, in one constant. The plugin's API client lets a request to Scenario's generation endpoint through only as a price check carrying that constant, or as the paid request carrying its own marker and no query string at all; anything else is refused before it is sent. Tests assert the exact query string of every price check and that no paid request carries the flag. Image inputs an action fills from the document later are priced without document pixels: by count where the price follows the number of files, or with a blank image of the right size where it follows their size. A price check that comes back with a job stops all price checks and says so in the panel. Each price is a quote that lasts 120 s, is used once and is bound to the exact request. *Tested automated*.
- **Generate**: the action, its prompt, the model and its settings, and the target the context card names: the layer, the selection (the result lands masked to it), the canvas, or a new document when none is open. A click on a priced button is the approval; above the confirm limit (100 CU; the top of a range; always for a `from` price) a card asks first. The request is built again at the click, so a document, selection or setting changed since the price check makes the quote mismatch and nothing is spent. The job record is written before anything is sent, keyed by the quote (a second click with the same quote sends nothing). The paid request goes once and is never retried: no answer within 60 s, a lost connection, a 5xx or an unreadable answer makes the job **Unknown**, which blocks the same request until you mark it not sent in Jobs; 400, 401, 402, 403, 404, 409, 413, 422 and 429 are not sent and charge nothing (a 429 pauses Generate for its Retry-After). The job is then polled (every 2 s, then 5 s, then 15 s), and the charge read from Scenario: a failed job shows "Refunded by Scenario". *Tested automated* against the mock API answering with the paid-job responses recorded live, through the plugin source on the real host adapter and through the release bundle, both over a fake Photoshop. *Not tested* in Photoshop.
- **References**: the refs row shows the document references first (a layer pinned with a role, Character, Set, Style or Product, kept in the document's XMP so it comes back with the file; a click leaves it out of one run), then this run's references; **+** adds the selection's box, the active layer, all visible, or a PNG or JPEG file. Captures are read as 8-bit sRGB at most 2048 px on the long side, sent as JPEG when the model takes it (Photoshop encodes it) and as PNG otherwise (the plugin's own encoder). Uploads go only through Scenario's API and must stay under 4,000,000 bytes: a capture read again 10% smaller until it fits shows **Input reduced**; a chosen file loses its metadata and is refused if still too large. References upload at the click; a price that changes once they are uploaded stops there and asks you again. An edit model takes them with its capture (GPT Image 2.5) or in its own reference input (Ideogram 4.5 Precise Edit, the Replace inside default: 4 at most, 3 with a selection); the **+** goes at the model's limit. *Tested automated*. *Verified live* on 27.11 with 0.7.0 dev: the refs row on Replace inside at 320 px, a layer reference added and sent to Precise Edit's reference input beside the capture and the mask. With a reference of the same scene, the Precise Edit take redrew that whole scene into the selection box; the checks flagged it (**Edge tone differs**, **May be misaligned**) and the pixels outside the selection stayed as they were.
- **Results**: each result downloads from Scenario's CDN (no key sent; the measured redirect is followed and its final host checked) into a `.part` file renamed when complete, three attempts, into the Output Folder in the plugin's data folder (`Scenario/<kind>/<date>/...`). It lands as an embedded smart object scaled to cover the target and centered on it, in one History state ("Scenario: Place image", "Place edit", "Expand", "Place upscale" or "Place cutout"), and your active layer is made active again. Several takes land as a group named after the action and the prompt, with take 1 visible. Each layer carries Scenario metadata (XMP schema 1: model, prompt, settings, ids, prices quoted and charged). A result lands by itself only in the Photoshop session and document that started it; otherwise Jobs offers **Place** and **Open as document**. *Tested automated* on a fake Photoshop. *Verified live* on 27.11 with a probe plugin: placing a file as an embedded smart object, its frame, scaling, one History state, layer XMP and layer masks. *Not tested* live as part of this build.
- **Takes card and Recent**: the run that landed shows as a card in the middle part with one tile per take, the price words and each take's check badge (**Edges ok**, **May not line up**, and after Remove **Part unchanged** when 30% or more of the selection came back as it was). A click on a tile shows that take in the document in one History state ("Scenario: Show take"); **Keep take N** removes the other takes in one History state ("Scenario: Keep take"; their files stay in the Output Folder and in Jobs); **Refine** keeps the shown take, loads the run's selection back from its mask and selects Replace inside; **More like this** runs again with the shown take as a reference. A group of takes selected in the Layers panel, now or after a restart, is the takes context: the card is rebuilt from the layers' Scenario metadata. Recent lists the other runs placed in this document; a click selects their layers. A run that did not land as takes (failed, waiting, or opened as a new document) shows one line and **Done**. *Tested automated* on a fake Photoshop.
- **Trained and Library (M7)**: **Run with** a trained model, the project's or a public one, from the Model menu or All models: it runs on its base for the selected action, with its trigger words (read from its record) put before the prompt unless Advanced leaves them out. A trained style and a trained model stack on one base when it takes both (two LoRAs, each with its own weight in Advanced); a composition runs alone, and a pick that cannot run with the other replaces it with a note. The Library grid has a search field, the filters All, Generated, Edited and Uploaded, and Show more; **Place from Library** (More > Layers) places an image in the document as a new layer at its own size, never enlarged, with Scenario metadata, in one History state. Drag from the grid is not in this build. *Tested automated* and headless at 280, 320 and 360 px. *Verified live* in Photoshop 27.11 with `test/live/m7-live-check.js`: Library browse, filters, search, Show more, place and + Reference, Run with, Make new and a selection edit on the FLUX.1 Dev and FLUX.2 Dev routes. *Not tested* live: the Z-Image route and a stacked run.
- **Look and live checks**: the panel follows the approved prototype of the creation flows at 280, 320 and 360 px. *Verified live* on Photoshop 27.11 with the 0.6.0 development build: the layer, selection, cut-out and takes contexts (the no-document one from the panel's state only: Photoshop hides docked panels on its Home screen) with real prices on the button and in the Takes menu; one run from the panel per flow (Create image into a new document, Replace inside and Remove on a selection, Make versions on a layer with the new layer selected afterwards, Cut out subject onto a new layer with the selection dropped), each in one History state with layer metadata and its file in the Output Folder; progress in the context card; the takes context read back from layer metadata after the panel reloads; Refine loading the run's selection back; More, the Model menu and the Jobs popover. The 320 and 360 px views were checked by widening the panel's root inside the 280 px dock, so width media queries still saw 280 px. *Not tested* live: the selection kept after a masked edit lands (fixed after the live run, tested automated), the Model menu's per-model prices and thumbnails (only the recommended model showed a price), Match an image and trained styles. *Tested automated and headless* since (not live yet): short panels keep every chip row whole and the button visible from about 380 px high at 280, 320 and 360 px (only the Takes and Recent part scrolls, Recent shrinks to one row of small thumbnails, then hides); thumbnails draw again (a naming clash in 0.6.0 left them blank and covered the prompt); **Suggest** in the composer (Scenario Prompt Spark: three fuller prompts from a short one, or a description of the active layer when the prompt is empty, sent only when its price check says 0 CU, picking one replaces the prompt and the run keeps the short prompt as its name); the **Change** chip on every edit model with a strength setting; the Model menu with each model's letters and its own price. *Verified live* on 27.11 with 0.7.0 dev, in a panel docked at 320 px: the layer and selection contexts (the refs row with **+ Reference** and its hint above the prompt), Make versions on a layer, Replace inside with a layer reference, Cut out subject on a selection, Place from Library, each in one History state with layer metadata and its file in the Output Folder.
- **Jobs**: the header's **Jobs** opens the jobs started on this computer, newest first, with status, the price words ("quoted 2, charged 2 CU", "Refunded by Scenario", "Charged 2 CU, no refund on failure", "Nothing charged") and the actions each state has. The job records in the data folder are the source of truth across restarts: one file per job, written atomically before anything is sent. *Tested automated*.
  - **After a Photoshop restart**: a job that was uploading or waiting for approval becomes not sent ("Interrupted by a restart", nothing charged); one that was being sent becomes **Unknown**; queued and generating jobs resume polling and finished ones resume downloading with fresh links; a job that was being placed waits to be placed again, unless its layer is already in an open document (Photoshop's crash recovery), in which case it is marked placed and nothing lands twice. Nothing lands in a document by itself after a restart. Jobs of another project wait until that project's key is in use. *Tested automated*: a restart at each of the six points (during upload, while sending, while awaiting approval, while generating, while downloading, while placing), held there by development-only test hooks.
  - **Unknown jobs**: Scenario's API takes no idempotency key, so the plugin looks the job up instead: by its job id when the record has one, otherwise in the project's jobs created from 10 minutes before the click to 60 minutes after it, matching the model and every recorded setting, the prompt included. One exact match is preselected and **Link** continues it (polling, download, placement); **Mark not sent** is offered only after a complete look-up in the last 10 minutes found no match. A look-up that could not finish offers **Check again** only. *Tested automated*.
  - **Downloads**: into `<name>.part` in the Output Folder, renamed when complete; a fresh signed link for every attempt, three attempts, an expired link (CDN 403) asked again, a result deleted on Scenario shown as such with **Open on Scenario**. **Stop download** and **Resume download**; a partial file restarts from zero. *Tested automated*.
  - **Placement after a restart**: a result goes to the document its job started from: the same document while Photoshop runs, or the same saved file (matched by a hash of its path) after a restart. While that document is closed or behind another, **Place** waits and says which document to open or bring to the front; **Place in current document** and **Open as document** are explicit choices. A document that was never saved cannot be found again after a restart. *Tested automated*.
  - **Errors** (from the responses recorded live): a refused key on a status read keeps the job and keeps reading; a 429 pauses for its Retry-After; offline pauses and resumes; a failed job shows as refunded, a job of a model without refunds as charged. *Tested automated*. The text of a content-policy refusal, a 429 and a key with a spending cap were not measured live, so those paths follow assumed answers.
  - The header's **Jobs** opens a short list of the six newest jobs (as in the prototype); a row or **All jobs** opens the Jobs view: each row's status, price words and actions (Approve, Decline, Place, Open as document, Resume download, Mark not sent with a second click to confirm, Copy error). The Unknown resolution card of the view model (`plugin/src/jobs/view-model.js`), with **Link** and **Check again**, is not drawn in the panel yet. *Tested automated*.
- **Edit and Enhance** (the logic behind the panel's edit, Extend canvas, Upscale and Remove background actions; a development entry also runs each route from a request file):
  - **Edit**: the selection, or the whole canvas without one, plus a margin (auto: the larger of 64 px and half the selection's long side), shaped to the sizes the model takes by growing, shifting or padding the box, read from all visible layers or the current layer at upload size, with a mask made from the selection (2 px feather by default) in the model's polarity. The result lands as an embedded smart object masked to the selection; several takes land as a group.
  - **Trained > Edit** (Experimental): one route per base model family. Change amount sends the capture as the image input with a strength (FLUX.1 Dev, Z-Image); Reference sends it as the first reference (FLUX.2 Dev and Klein, Qwen); Mask uses the base model's mask input. A LoRA goes with its scale, a composition by its model id.
  - **Expand**: to a ratio or by sides, on three routes. Mask sends the grown canvas with a mask over the new area and a 32 px overlap; Position lets the model place the original from a position and a ratio; Exact size sends the output width and height (center only). The canvas grows in the same History state as the placement.
  - **Upscale**: the document, the current layer or the selection's box, at a factor the model offers, capped at its largest output; it lands as a new document, a layer or into the box.
  - **Remove BG**: lands as a mask on the layer (the Background is converted first, in the same History state) or as a new cutout layer, the only choice for a layer that is masked, locked, text, shape or a group.
  - **Checks after placement**: a seam ring around the edited area (tone bias and residual), whether anything changed inside, whether pixels outside the mask changed (**Changed outside**, with **Undo**), the result's aspect, and a mask that looks inverted. A failed check adds a badge or a note and never removes the result, which stays saved and can be placed again.
  - A capture is read again 10% smaller until it fits the upload limit. For Edit this shows **Input reduced**; for Upscale and Remove BG, whose output follows the input, it stops before anything is spent and the price is checked again at the size that fits.
  - *Tested automated* on a fake Photoshop that composites real pixels, against the mock API answering with recorded responses: captures, masks, shaping, every paid path above, the checks on synthetic pixels with known defects, and that a failed check keeps the paid result.
  - *Verified live* on Photoshop 27.11 with the 0.4.1 development build, one take per route on a synthetic 768 x 512 document, run from the development entry: Edit (GPT Image 2.5 Flare), Expand on the mask route (GPT Image 2.5 Flare), the position route (Reframe) and the exact-size route (Photoroom Expand), Upscale 2x to a new document (Topaz), Remove BG as a mask on the Background (851 Labs), and Trained > Edit on the image and strength route (FLUX.1 Dev with a public LoRA) and the reference route (FLUX.2 Dev with a public LoRA). Each landed in one History state, every charge matched its price, and on every masked route the pixels outside the mask were unchanged. The checks flagged the takes that did not line up: the Flare expand and the FLUX.1 Dev edit (the model redrew the scene) show **May be misaligned**, and the Photoroom expand was placed unmasked for manual alignment. *Not tested* live: the trained mask route (no catalog base uses it yet), Upscale and Remove BG landings other than the two above, and the panel. The Expand check measures whether the original lines up on the overlap; it does not judge the new area's content at the edge (a Reframe take whose new hills stop flat at the old edge passed it).
- **Helper** (`helper/`, npm package `@scenario-labs/photoshop-mcp`, command `scenario-photoshop`): an MCP server over stdio with the 29 tools of the v1 catalog (`shared/catalog.json`, reference in [spec/MCP.md](spec/MCP.md)); the plugin serves them and the helper relays each call with its own time limit. `scenario_status` reports whether the plugin is linked, the Photoshop and plugin versions, whether the plugin is signed in and the project name (never the key), the agent switches and spending settings, and the open documents (ids and titles). `list_models` and `model_schema` read the catalog; `estimate_cost` validates a request and returns a quote from a free price check. *Tested automated*, through a real helper process. *Verified live* on Photoshop 27.11: this build loads, links and answers `scenario_status`. `list_models` and `estimate_cost` were also *verified live* (0.3.1, signed in): the three recorded prices, 2, 3 and 1 CU, came back exact.
- **Agents** (M6): agents read documents, capture and upload references, price and run generations and land results through the tools above. Three switches in Settings > Connect an AI agent (modify the document, run Photoshop commands, read the active document only), No-spend, and Agent spending (Ask each time, or Allow per call and in total for one client session). A spend card shows in the composer before any agent spends (Approve, Decline); a card asks before an agent first sends a document's pixels; with modify off, results wait on a proposal card (Apply, Dismiss). Every change is one History step "Scenario agent: <action>" on the document in front only. `execute_batchplay` runs Photoshop commands through an allow-list (SPEC 6.6). *Tested automated* (unit tests and two end-to-end runs through a real helper process). *Verified live* on 27.11 (M6, dev loop): a reference chain without a document element resolves in the active document; `select_layers` adds no History state; Select Subject runs as one "Scenario agent: Select" step; commands on a document that is not in front return `DocumentNotActive` with its History unchanged. Also *verified live*: every allowed event once (46 of 47 committed; the Apply Image test descriptor was refused by Photoshop), the refusals against a second document with its History unchanged, the proposal card, No-spend, and a headless Claude Code session through the setup command's config that read, selected, uploaded, priced, got one spend approved and landed it as one History step with layer XMP, then had a second request declined at 0 CU. A first pass met a modal Photoshop error alert under `dialogOptions: dontDisplay`; agent descriptors now run with `silent`. *Verified live* on 27.11 with 0.7.0 dev: a client on the helper priced a Create image (2 CU), its spend card was approved with a click in the panel, and the result landed through the proposal card (**Apply**) as one History step "Scenario agent: Place image" with the agent named in the layer metadata. That run found the upload and proposal cards hidden by the stylesheet (the F5 card's rule); fixed in 0.7.0.
- **Several clients at once**: the first helper owns port 9890 on `127.0.0.1` and `::1`; later helpers relay through it; when the owner exits, another takes over and the plugin reconnects. Each client gets a session (a random 128-bit id, new each time the plugin links) and keeps the name it gave at its first `initialize`; the panel lists clients by that name, and the plugin refuses calls from a session that is not on its list. *Tested automated* (macOS). *Not tested* on Windows.
- **One Photoshop at a time**: if a second Photoshop with the plugin reaches the helper, it is refused and its panel says "Agents are connected to another Photoshop"; the first keeps the link. *Tested automated*.
- **Pairing**: the plugin makes a 256-bit token and keeps it in UXP secure storage. The token never travels over the socket: both sides prove they hold it with HMAC-SHA-256 over fresh nonces, then every message carries a MAC and a counter. The helper also checks the `Host`, `Origin` and `User-Agent` headers before any protocol byte. *Tested automated*, including wrong tokens, replayed and tampered messages, programs squatting on the port, and browser-like connections.

## Connect an agent client from a checkout

The setup command reads the pairing token from the `SCENARIO_PHOTOSHOP_TOKEN` environment variable (or stdin with `--token-stdin`), never from a command argument. It writes the token to a file only your account can read (`~/.config/scenario-photoshop/token`, or `%APPDATA%\scenario-photoshop\token`), then registers the server with the client without the token: through `claude mcp add` or `codex mcp add`, or in the Cursor or Claude Desktop config file (with a backup of the old file).

```sh
# Token copied from the Scenario panel; nothing is written to your shell's argument list.
pbpaste | node helper/bin/scenario-photoshop.js setup claude-code --local --token-stdin
```

*Tested automated* with temporary home folders and a stand-in for the client CLIs. *Tested headless* (M6) for the four clients against temporary config files: no entry holds the token, new files are 0600, the token file 0600 in a 0700 folder; Codex through the real `codex` CLI with a temporary `CODEX_HOME`. Cursor's own handling of the file is *not tested* (not installed), nor Windows. The npm package is not published yet. The user walkthrough is [MCP.md](MCP.md).
